# kbve-proto

The Rust view of the KBVE protobuf schemas.

Every language KBVE consumes is generated from one `buf generate` run against
`packages/proto`, so a schema change that breaks one of them fails locally
rather than in whichever downstream repository builds first. This crate is the
Rust half of that output: the prost message types for the content domains
(`item`, `npc`, `quest`, `map`, `spell`, `dialogue`) and the service domains
(`jedi`, `redis`, `clickhouse`, `twitch`, `git`, `groq`), plus the handful of
conversions that the generated code cannot express on its own.

```toml
kbve-proto = "0.1"
```

## Features

| feature  | what it adds                                                              |
| -------- | ------------------------------------------------------------------------- |
| _(none)_ | The message types. This is the default.                                   |
| `grpc`   | The tonic clients and servers for `RedisService` and `ClickHouseService`. |

gRPC is behind a feature because the generated clients and servers drag in
axum, hyper, h2 and tower. A Bevy crate that wants an item definition should
not compile an HTTP/2 stack to get one.

## ULIDs

The schema carries a ULID as its sixteen bytes rather than its twenty-six
characters, and says the textual encoding belongs at the edges. JSON is such an
edge, so `kbve.type.v1.Ulid` is declared to serde through `UlidText`: hand-written
content files say `"01KKR5QWTA6KARZ9EQB9Y476S4"` and the wire still carries
bytes. `ulid_text` renders one on demand.

## Generated code

`src/gen` is generated by `moon run protobuf:build` and committed. It lives
inside the package rather than in `packages/proto/gen` because `cargo package`
does not carry a path that escapes the package root -- a crate that included it
from there would build in the workspace and fail for everyone who installed it
from the registry.

Do not edit `src/gen` by hand. Change the `.proto` and regenerate.
