# Stalwart — MTA-only mail for `$username@herbmail.com`

[Stalwart](https://github.com/stalwartlabs/stalwart) runs as an MTA only. It
terminates SMTP on the shared public IP, runs SPF/DKIM/spam checks, then fires
an [MTA hook](https://stalw.art/docs/api/mta-hooks/overview/) (data stage) at
`axum-herbmail`, which resolves recipients against `profile.username` and
inserts rows into `mail.messages` (supabase). The hook answers
`{"action": "discard"}` on success, so **Stalwart never stores mail** — the
`mail` schema is the single copy, purged after 90 days by `pg_cron`.

Internal user-to-user messages insert straight into `mail.messages`
(`via='internal'`) and never touch SMTP.

## Architecture

```
external MX traffic :25/:465/:587
        │  (shared LB IP 142.132.206.71, sharing-key public-71)
        ▼
Stalwart (ns stalwart, MTA-only, config + registry in kilobase stalwart schema)
        │  MTA hook POST /hooks/stalwart  (Bearer STALWART_HOOK_SECRET)
        ▼
axum-herbmail (ns herbmail) ── rpc stalwart_ingest ──▶ mail.messages (supabase)
```

## One-time setup

1. **Migrations** — `ci-dbmate-deploy` applies:
   - `20260807120000_stalwart_role_schema.sql` — `stalwart` role + schema,
     `search_path` pinned so Stalwart's tables land in its own schema.
   - `20260807121000_mail_schema_init.sql` — `mail.messages`, RLS,
     `public.stalwart_ingest` RPC, pg_cron purge (90d).
2. **Role password** (prod):
   `ALTER ROLE stalwart WITH PASSWORD '<password>';`
3. **Bootstrap admin** — first boot prints temporary admin credentials:
   `kubectl logs -n stalwart deploy/stalwart | grep -A8 'bootstrap mode'`
   Admin UI via `kubectl port-forward -n stalwart svc/stalwart 8080:8080`.
4. **Setup wizard** — storage backend **PostgreSQL**:
   host `kilobase-rw.kilobase.svc.cluster.local`, db `supabase`,
   user `stalwart` (tables land in the `stalwart` schema via search_path).
   Hostname `mail.herbmail.com`, local domain `herbmail.com`.
5. **MTA hook** — in admin, add hook:
   url `http://herbmail-service.herbmail.svc.cluster.local:4321/hooks/stalwart`,
   stages `data`, auth Bearer = value from
   `apps/kube/herbmail/seal-stalwart-hook-secret.sh` (same sealed secret feeds
   `STALWART_HOOK_SECRET` in the herbmail deployment).
6. **TLS** — `stalwart-tls` Certificate (mail.herbmail.com) is mounted at
   `/opt/stalwart-tls`; point the TLS cert/key paths there in admin.

## DNS (registrar side)

| Record | Value |
| --- | --- |
| `mail.herbmail.com` A | `142.132.206.71` |
| `herbmail.com` MX | `10 mail.herbmail.com` |
| SPF TXT | `v=spf1 ip4:142.132.206.71 -all` |
| DKIM TXT | generated by Stalwart admin — publish before sending |
| DMARC TXT | `v=DMARC1; p=quarantine; rua=mailto:postmaster@herbmail.com` |
| PTR (provider panel) | `142.132.206.71` → `mail.herbmail.com` |

## Caveats

- **Source IP**: the LB IP is shared with the Cilium gateway
  (`sharing-key public-71`, default `externalTrafficPolicy: Cluster`), so
  Stalwart may see node-SNAT'd client IPs. That weakens SPF/DNSBL/rate limits.
  If it matters, test `externalTrafficPolicy: Local` (must not break IP
  sharing) or move to a dedicated IP in the LB pool.
- **Outbound**: sending (agent replies) leaves via the submission port; keep
  new accounts reply-only and rate-limited in Stalwart before opening
  arbitrary outbound send. One spam burst torches the domain's reputation.
- The bootstrap `STALWART_RECOVERY_ADMIN` backdoor env is intentionally NOT
  configured; bootstrap-mode credentials come from the pod log instead.
